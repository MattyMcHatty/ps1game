RAM RECLAIM — PLAN AND LIVE CHECKLIST  (started 2026-10-03)
==============================================================
Why: every room costs ~13.6 KB of PERMANENT main RAM (it moves _end), whatever
area the player is in. Texture banking cannot help with that. FREE AT REST
fell to 120 KB when the Zig Zag Tomb went in, under heap_budget.py's 128 KB
warning line.

Baseline (with the Zig Zag Tomb in, before any of this):
    _end            0x80136664
    FREE AT REST    122,588 bytes (120 KB)

Order: PART A (room data out of the executable), then PART B (compact room
state). Each part builds, makes a disc and boot-tests on its own.

Legend:  [ ] to do   [~] in progress   [x] done   [!] problem, see note


##########################################################################
 PART A — ROOM DATA OUT OF THE EXECUTABLE           expected: ~110 KB back
##########################################################################
What moves: each room's per-poly texture map, its no-cull table and its
collision walls. Today they are compiled into HORROR.BIN and sit in RAM for
the whole game (68 KB of maps + 50 KB of collision code, 43 rooms). After this
they ride at the end of the room's own .SMD file and arrive in the room arena
with the mesh, so only the CURRENT room's copy is ever in RAM.

What does NOT change: the generators (gen_<slug>_tex_map.py,
smx_to_collision.py), the files they write, and hand edits in
src/<slug>_mesh_collision.c. Those stay the source of truth. A new build step
reads them and packs the data. The dresser and grinder tex maps are props, not
rooms, and stay where they are.

  [x] A1  Data format. One block appended after the SMD bytes:
            header   magic, prim count, wall count, bounds, multi_level,
                     shoot_over_mask
            prim map 1 byte per prim: low 7 bits = texture slot (0x7F =
                     untextured), bit 7 = never backface-cull. That merges the
                     two tables into one byte, which is half the size.
            walls    8 x int16 each (every coordinate in the game fits; checked)
            footer   last 8 bytes: block offset + magic
          smdInitData ignores bytes after the mesh, so the SMD itself is
          untouched.

  [x] A2  tools/pack_rooms.py. For each of the 43 rooms, it parses
          src/<slug>_tex_map.h and src/<slug>_mesh_collision.c, and writes
          build/rooms/<DISCNAME>.SMD = assets/<slug>.smd + the block.
          assets/<slug>.smd itself is never modified.
          FAILS THE BUILD on anything it does not understand: a statement that
          is not a literal assignment, a wall with a missing field, a value out
          of int16 range, more than 128 walls, or a prim count that does not
          match the SMD's own header.
          One special case: the kitchen's collision file has a
          #ifdef DEBUG_COLLISION loop that sets every wall to y[-600,-375], and
          DEBUG_COLLISION is ON. The packer reproduces it exactly.
          RESULT: all 43 rooms pack, nothing rejected. 60,936 bytes of room
          data now ride on the disc. The biggest file, MAZEONE.SMD, grows by
          3,576 bytes.
          FORMAT TWEAK FROM A1: the texture map keeps its exact old byte values
          (0xFF = untextured) and no-cull is a separate 1-bit-per-prim set, so
          every existing use, including Room of Arms' and Asag's special
          ones, is a straight rename.

  [x] A3  CMakeLists.txt: the packer runs on every `cmake --build`, before the
          link. The 43 *_mesh_collision.c files leave add_executable.

  [x] A4  disc.xml: the 43 room SMD entries read build\rooms\ instead of
          assets\. Same disc names, so no directory grows.

  [x] A5  src/room_data.c/.h (new):
            room_data_bind()      - after room_arena_load, finds the block and
                                    points room_prim_map at it
            room_data_collision() - fills current_collision_room from it (all
                                    zero when there is none: walls nowhere,
                                    which is loud rather than silently stale)
          room_arena_load() also records the file's exact size, so the footer
          can be found.

  [x] A6  tools/gen_room_arena.py sizes the arena from the PACKED files.
          (Maze One grows ~4 KB, which is the one cost of this part.)
          RESULT: arena 58 -> 60 sectors (118,784 -> 122,880 bytes), as predicted.

  [x] A7  The 43 room modules, three mechanical edits each:
            _load_geometry : room_data_bind(); no block -> mesh NULL (draws empty)
            draw loop      : read room_prim_map[i] instead of <slug>_tex_map[i]
                             and <slug>_nocull[i]
            _init          : room_data_collision() instead of
                             <slug>_collision_init()
          plus collision.c's startup collision_init(), which runs before any
          room is loaded and becomes "zero the room".
          RESULT: all 43 done by script, each edit required to match exactly
          once. Delivery is the one room whose walls come through collision.c
          (collision_init), not its own init.
